# 学员任务与提交要求

本仓库只提供可运行的 PX4/Gazebo 环境，不提供任务解法。允许查阅并引用 PX4、ROS 2、Gazebo 官方文档；提交时要说明参考来源，且能在面试中解释自己的代码。所有飞行必须由 PX4 控制，禁止通过 Gazebo `set_pose`、模型移动命令或视频后期合成代替飞行。

## 26 级：基础往返

自行编写 ROS 2 节点，令 x500 从黄色 A 桌面起降圈起飞，绕过房间中央隔墙到达蓝色 B 桌面起降圈，再绕墙返回 A，最后在 A 桌面降落并解除解锁。A/B 在 Gazebo ENU 中分别约为 `(0, 0)` 和 `(7, 0)`；直线连线被实体墙阻断，不能穿墙或从顶棚上方绕行。规划前先确认 PX4 NED 坐标及实际位置反馈。请实现基于真实位置的到点判定、连续 Offboard 控制信号、避障航点、阶段超时与失败处理。飞行高度必须兼顾 0.77 m 桌面、4.2 m 顶棚和机体尺寸。预计准备 2–4 天。B 桌面具备降落能力；是否要求在 B 实际降落，以最终考题说明为准。

## 25 级：可配置航线

在同一封闭房间中实现 A→B→C→A，所有跨越隔墙的路段都必须从两侧通道绕行。C 由本人选择，需给出坐标、与墙和房间边界的安全间距，以及选择该侧通道的理由。航点与飞行参数应从配置读取，至少演示两组配置；加入速度限制、单段超时，以及通信/模式异常的一种恢复或安全终止策略。预计准备 3–5 天。

## 统一提交

1. 代码、依赖说明、启动命令与约 300 字设计说明。
2. 连续 Gazebo 画面或原生仿真摄像机录像，以及 PX4 实际位置/状态记录；仅有视频不算完成。
3. 成功与失败的判定依据、至少一次遇到的问题及处理过程。

面试将重点讨论：坐标系、绕墙路径与机体安全间距、为什么要持续发送 Offboard 信号、如何判断真正到点、何时允许切换阶段、如何在桌面安全降落、模拟室内定位不能直接推广到真机的原因。

可参考 [PX4 ROS 2 入门](https://docs.px4.io/v1.16/en/ros2/user_guide)、[Offboard 控制说明](https://docs.px4.io/v1.16/en/flight_modes/offboard) 和 [ROS 2 Python 包教程](https://docs.ros.org/en/humble/Tutorials/Beginner-Client-Libraries/Creating-Your-First-ROS2-Package.html)。这些公开材料不是仓库内的现成答案。
