# 无人机仿真选拔考核与提交要求

本仓库只提供可运行的 PX4/Gazebo 环境，不提供任务解法。允许查阅并引用 PX4、ROS 2、Gazebo 官方文档；提交时要说明参考来源，且能在面试中解释自己的代码。所有飞行必须由 PX4 控制，禁止通过 Gazebo `set_pose`、模型移动命令或视频后期合成代替飞行。

## 统一考核任务：可配置航线

所有候选人完成同一套任务，不按年级区分。自行编写 ROS 2 节点，在本仓库的封闭房间中控制 PX4 x500 完成：

**A 桌面解锁起飞 → 绕墙到达 B → 到达自选 C 点 → 返回 A → 在 A 桌面降落并解除解锁。**

B、C 为飞行到达点，本题不强制在 B、C 降落；B 点降落后再起飞可作为自行扩展。预计准备 3–5 天，此为工作量参考，具体截止时间由组织者另行通知。

## 场景与路线要求

- A/B 在 Gazebo ENU 中分别约为 `(0, 0)` 和 `(7, 0)`，起降圈位于约 `0.77 m` 高的桌面上。
- 中央实体隔墙阻断 A/B 直线连线。所有跨越隔墙的路段必须从隔墙两侧通道之一绕行，不得穿墙或从顶棚上方绕行。
- C 由本人在房间内选择，应与 A、B 为不同位置。提交时说明 C 的坐标、所用坐标系、与墙和房间边界的安全间距，以及所选通道的理由。
- 飞行高度须兼顾桌面、约 `4.2 m` 高的顶棚和机体尺寸。先核对 PX4 本地 NED 坐标与 Gazebo ENU 的关系，不能直接把世界坐标当作飞控坐标。
- 允许自行设计绕墙中间航点；本题不强制实现激光雷达建图、A*、SLAM 或 AprilTag 识别。

## 必须实现的功能

1. **飞行状态管理**：完成 Offboard 信号预发送、模式切换、解锁、起飞、巡航、返航、降落及解除解锁；持续发送所需控制信号，并读取 PX4 实际位置和状态反馈。
2. **基于反馈的到点判定**：自行设定并说明位置误差阈值和稳定到点条件。不得仅以固定等待时间冒充到点。
3. **配置化航线**：从配置文件读取航点与飞行参数，至少包括航线、巡航高度、速度限制、到点阈值和单段超时。至少演示两组不同配置，说明差异；切换配置无需修改控制逻辑源码。
4. **速度限制与超时**：说明如何约束飞行速度；任一航段超时后应进入明确的失败处理流程，不能继续宣布任务成功。
5. **异常处理**：针对通信或飞行模式异常，至少实现一种恢复或安全终止策略，并演示一次异常触发及处理结果。说明触发条件、检测依据、程序采取的动作和 PX4 的实际响应。
6. **结果记录**：保存 PX4 实际位置和飞行状态，以及关键阶段切换、到点和异常事件，能够据此复核任务是否完成。

## 统一提交

1. 自编 ROS 2 功能包源代码、两组配置文件，以及可复现的依赖说明和启动命令。
2. 约 300 字设计说明，说明状态流程、坐标系、C 点选择和绕墙路线。
3. 两组配置各一次完整任务录像，以及一次异常处理演示。保留连续 Gazebo 画面或原生仿真摄像机录像，标明对应配置。
4. 与录像对应的 PX4 实际位置/状态记录、关键事件日志；仅有视频不算完成。
5. 成功与失败的判定依据、两组配置结果的简要比较，以及至少一次遇到的问题及处理过程。

任务成功应有记录证明：依次完成 A 起飞、B 到达、C 到达、返回 A、A 桌面降落和解除解锁，且未发生碰撞或越界。异常测试单独说明预期结果，按预期安全终止不等于完整航线任务成功。

面试将重点讨论：坐标系、绕墙路径与机体安全间距、为什么要持续发送 Offboard 信号、如何判断真正到点、何时允许切换阶段、如何在桌面安全降落、模拟室内定位不能直接推广到真机的原因。

可参考 [PX4 ROS 2 入门](https://docs.px4.io/v1.16/en/ros2/user_guide)、[Offboard 控制说明](https://docs.px4.io/v1.16/en/flight_modes/offboard) 和 [ROS 2 Python 包教程](https://docs.ros.org/en/humble/Tutorials/Beginner-Client-Libraries/Creating-Your-First-ROS2-Package.html)。这些公开材料不是仓库内的现成答案。
